# 第8章：LLM 工程实践与部署

## 章节概览

本章回答一个核心问题：**如何把 LLM 应用稳定、可控、可负担地上线？**

![LLM 工程生产反馈闭环](/diagrams/ch08-engineering-feedback-loop.svg)

*章节主图：LLM 工程生产闭环。系统不仅要产生回答，还要持续以质量、延迟、成本、可靠性和安全信号驱动路由、配置与版本迭代。*

本章主线是生产闭环：**量化 / 剪枝 / 蒸馏 → 推理优化 → 成本控制 → 评估监控 → 云端与端侧部署**。第 5 章解释模型怎么训练，第 6 章解释应用怎么设计，第 7 章解释不同信号怎样与语言对齐，第 8 章负责把这些能力变成可运行、可观测、可回退的工程系统。

## 核心问题

完成本章后，你应该能回答：

1. 量化、剪枝和蒸馏分别解决什么问题？代价是什么？
2. KV cache、批处理和推理框架如何影响吞吐与延迟？
3. LLM 服务的成本主要由哪些因素决定？
4. 为什么离线 Benchmark 不等于线上质量？
5. 一个生产级 LLM 系统需要哪些监控、回退和风险控制机制？
6. 为什么端侧多模态不能只用参数量和模型文件大小验收？

## 本章学习闭环

1. 先根据章节主图为一个云端或端侧多模态服务定义质量、延迟、内存、可靠性和安全目标；
2. 运行 `cost_calculator.py` 或 `inference_benchmark.py`，得到至少两种配置的可比较结果；
3. 完成最低实践任务，基于测量结果选择方案并写明收益、代价和适用边界；
4. 为所选方案补充监控指标、告警阈值和回退条件，形成从评估到生产反馈的闭环。

## 最低实践任务

给一个假设的云端 LLM 服务或端侧多模态系统设定质量、延迟、内存、成本和可靠性目标，使用本章的成本计算或推理基准脚本比较至少两种方案，并写出一个监控与回退条件。完成标准：方案选择必须同时说明保留了什么信息、牺牲了什么，以及失败时如何处理。
