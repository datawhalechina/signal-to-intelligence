# 章节项目与综合项目

本目录用于存放“最低实践任务”之上的完整项目。它与 `code/` 的职责不同：

- `code/` 保存可复用的算法实验和演示实现，是算法源头；
- `projects/` 保存围绕一个问题组织的实验流程、对照方案、评估和结论；
- `notebooks/` 保存交互式讲解和参数探索，不复制核心算法；
- `docs/` 解释项目背后的概念、主线和工程取舍。

## 当前阶段的组织方式

最低实践任务直接复用现有 `code/chXX_*/` 脚本，不为每个任务单独新建文件。

当一个任务需要多个实验、指标、失败分析或综合报告时，再创建一个独立项目目录：

```text
projects/<project-name>/
├── README.md          # 问题、目标、实验设计、结果和结论
├── main.py            # 统一入口，负责编排实验
├── experiment.py      # 项目特有的数据处理或实验逻辑
├── evaluate.py        # 指标和对照分析（需要时再添加）
├── tests/             # 项目行为测试（需要时再添加）
└── outputs/           # 本地生成物，不提交
```

项目脚本应优先调用 `code/` 中已有的函数或模块。只有当逻辑确实属于项目编排、评估或数据处理时，才在项目目录中新增代码。

## 项目最低要求

每个章节项目至少应包含：

1. 一个明确的问题和输入输出；
2. 一个可运行的基线；
3. 一个关键因素的对照实验；
4. 一个能够解释本章主图的结果图；
5. 一个失败案例或限制说明；
6. 一段说明结果如何支持或修正本章核心结论。

项目后续可以逐步增加真实数据、更多基线、评估指标、资源约束和部署方案，但不要求第一版一次完成所有深度内容。

## 建议的项目层次

```text
最低实践任务：复用已有脚本，完成一次参数修改和解释
    ↓
章节项目：多个实验 + 对照 + 指标 + 失败分析
    ↓
综合项目：跨章节串联表示、建模、应用和工程约束
```

综合项目不预设为 RAG 项目。它可以根据教程主线逐步演化为信息表示、注意力/预测、外部信息或工具接入、评估和部署权衡的完整系统。

## 项目路线图

项目按模态和系统复杂度分阶段建设：

### 第一阶段：检测与识别基线

```text
projects/
├── signal_detection/
└── vision_detection_comparison/
```

先建立传统信号检测和视觉目标检测的对照基础，验证“表示 → 检测 → 评估”的项目模板。

### 第二阶段：非视觉信号与跨模态表示

```text
projects/
├── audio_event_detection/
└── image_text_retrieval/
```

`audio_event_detection/` 不是单纯的音频分类项目，而是第一个“非视觉信号—语言对齐”模板：比较波形、时频图和事件 token，建立事件标签或文本描述，并分别评估信号识别与跨模态匹配。`image_text_retrieval/` 提供视觉侧对照，帮助判断哪些对齐问题与模态无关，哪些来自具体表示。

### 第三阶段：综合多模态系统与端侧验收

```text
projects/
└── multimodal_system/
```

综合多个章节，增加外部信息或工具接入，并设置一个明确的端侧配置作为验收环境。项目同时记录信号保真、跨模态对齐、任务输出、峰值内存、延迟和功耗；端侧不是单独的部署演示，而是检验表示效率的约束条件。
